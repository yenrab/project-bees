# Silica defects found while building BEES

Findings about the Silica toolchain: defects and surprises in the fixed-point compiler and
runtime. BEES never fixes them in Silica (AI_POLICY.md: a person files and lands each one); the
trial named here is the reproducer, and `trials/silica_defects/` holds the ones with their own
program. A BEES-side workaround is recorded only where it keeps to the BEES design; where it would
not, the row says what decision is needed. Compiler generation is in `tools/silica.generation`.

| # | Found | What | Reproducer | BEES workaround |
| --- | --- | --- | --- | --- |
| SD-1 | 2026-09-17 | A cross-module call with **too many** arguments compiles. `answer/1` called as `mod@answer(1, 2)` passes; too few arguments is rejected (E2005), as in Silica's own `qualified_call_wrong_arg_count_trial`. Same on `silica-999977`, `silica-999982` and `silica-gen2`. | `trials/r01_harness/fail_wrong_arity.silica` (uses too few arguments so it fails as intended; the comment records the too-many case) | None needed; noted so that a BEES trial never relies on the compiler catching extra arguments. |
| SD-2 | 2026-09-17 | `project_makefiles/Makefile` links without `-Wl,-e,main`, so a program built with the drop-in Makefiles fails to link ("Undefined symbols: _main"). The trial makefiles pass the flag. | Any program built with `project_makefiles/` | `tools/silica.mk` passes `-Wl,-e,main`. |
| SD-3 | 2026-09-17 | **Atom tables are per compilation unit.** Each unit numbers its own atoms from 23 by first appearance and emits the number as an immediate, so an atom minted in one unit is a different atom in another (spike S2). Contradicts spec §4.1.7 (one program-wide table). This is Track S item **S-1**, now confirmed. | `trials/s02_cross_unit_atoms/` (golden records today's wrong output) | None that keeps the design without a decision: an atom prelude injected into every unit (see the S2 spike note) would coordinate numbering but adds a contract obligation. **Blocks everything; needs a decision.** |
| SD-4 | 2026-09-17 | `ref?(L, normal, (T…, ref?(L, normal, rec)))`, the optional recursive reference with its tuple type spelled out, is not treated as equal to `ref?(L, normal, rec)`: E2003 both when passed to `alloc_rec` and when a ref is stored into a field of that type. The recursive-tuple specification allows the spelled form. | `trials/silica_defects/fail_sd4_ref_opt_spelled_type.silica` | Write every optional recursive reference as `ref?(L, normal, rec)`, as the stdlib does. Design-neutral. |
| SD-5 | 2026-09-17 | `ref?(…)` is not parsed as the type annotation of a sequence binding (`x: ref?(L, normal, rec) <- …` is E1040; spelled out, E1069), although it is accepted for parameters, returns, record fields and tuple patterns. | `trials/silica_defects/fail_sd5_ref_opt_binding_annotation.silica` | Bind through a function whose return type is `ref?(L, normal, rec)` or through a record field. Design-neutral. |
| SD-6 | 2026-09-17 | Lifetime names in signatures are matched **nominally** at call sites: a function over `region(L, …)` rejects a `region(M, …)` argument (E2003). Spec §12 reads as if lifetime identifiers were variables. Possibly by design. | `trials/silica_defects/fail_sd6_lifetime_name_nominal.silica` | Every BEES unit names the term lifetime `L`, and every region that carries terms is typed `region(L, normal)`. Design-neutral, but the contract must say so (item 1). |
| SD-7 | 2026-09-17 | **A region moved into a message is never reclaimed** after the receiving behaviour returns: 100,000 casts each carrying a fresh two-cell region reach 550 MB peak RSS (~5.5 KB each), against 17 MB for int64 casts and 9 MB for 100,000 regions dropped at function scope exit, which are reclaimed. Spec §12.1.6 moves ownership to the receiver; nothing frees it. | `trials/silica_defects/sd7_message_region_never_freed.silica` (measure with `/usr/bin/time -l`) | None within the design yet: BEES messages are `bees_term` values in regions, so every message would leak. Candidates: (a) wait for a Silica fix, possibly as part of S-15; (b) carry message terms region-free (flat encoding) and rebuild them in the receiver's region, which changes contract item 1 for messages. **Needs a decision.** |
| SD-8 | 2026-09-17 | `cast()` to a behaviour that returns `(:reply, R, S)` (call-only, §16.2.6.1) faults at run time inside the behaviour when the state is a record or tuple (`[silica] fault … addr=0x…06`); with an `int64` state it silently works. No diagnostic at compile time or at the call site. | `trials/silica_defects/sd8_cast_to_call_only_behaviour_faults.silica` | BEES processes are cast-only actors returning `(:no_reply, state)`, as D5 already requires; the run-time check is S-31. Design-neutral. |
| SD-9 | 2026-09-17 | **A `call` whose callee dies returns the zero value of the reply type** (`0` for `int64`), indistinguishable from a genuine reply; the same for a call to an already-dead actor. Silica's own trials (`actor_call_after_abnormal_kill_returns_death`) record this. Spec §16.1.1 says the call "raises `actor_not_found`", which a language without exceptions cannot mean; this is the open question in Track S item S-9. | `trials/s10_failure_paths/bif_failure_restarts_child.silica` (the two `0` lines) | None within the design: BEES cannot fail the caller (D2) on a death it cannot see. For a `bees_term` reply the zero value is a null region reference. **Needs S-9's answer.** |
